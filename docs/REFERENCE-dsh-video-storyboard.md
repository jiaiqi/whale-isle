## 1. 结论摘要

**视觉复盘层的算法与纪律来源**：把视频压成"一张切点密度自适应宫格图（≈222–233 token）+ 一份带时间码文本清单"，让模型"看过"一段视频的 token 成本只有抽帧方案的 1/2–1/4.5。设计纪律（证据文件、只给原材料不下结论、诚实对比竞品）是全生态最严格的。定位与 SPEC §3.6 一致：**视觉只做事后复盘，不进实时控制**。

## 2. 采用什么

- **证据与复核**（`.evidence.json`）：每次出图同时写一份机器可读证据（每格起止时间、取帧时刻、刀数、字数、原文），"给人和脚本复核"——我们高光/翻车切片的**证据链格式**直接采用（切片草稿必须带可回看的时间码证据）。
- **token 预算意识**：
  - `auto` 档按视频时长定张数（≈4 分钟/张）再在预算内挑"最小格还认得出"的最省档——"模型看不见多一张图多少钱，所以选档这件事收回工具自己"；
  - `dryRun: true` 先扫描报价不出图；
  - token 按像素计费（42px 网格、地板 544²、封顶 994）。
  ——我们"严格受每日视觉预算上限控制"的实现规格参照（视觉模型调用前先报价、记账）。
- **转写优先级**：视频自带字幕轨 → 已有 SRT/JSON → ASR（第一个能用的赢，零成本路径优先）——切片复盘的字幕来源顺序。
- **ASR 生命周期托管**：本机 sherpa（冷启动 5s → `idleMs` 5 秒随用随关）/ funasr（冷启动 30s → `idleMs` 10 分钟）；服务约定 `GET /health` / `POST /shutdown` / OpenAI 兼容转写端点——我们 Python Sidecar 的进程托管约定可直接沿用。
- **热词与术语校正**：热词**按片传**不写死全局（全局词表是负偏置）；`terms` 表确定性替换且替换次数报在清单里不静默。
- **OCR 抽检口径**：硬字幕校正只抽查并明写 `spot-checked N lines, corrected M`，**不冒充全片校对**——VERIFY 证据口径范例。
- **清单设计三原则**（原文）：① 清单只给原材料不下结论；② 每加一行都要能说出它挡掉了什么误判；③ 数字不可信时要说出来（如 `cut count unreliable here`）——我们视觉复盘 Prompt 设计的原则。
- **诚实对比文化**：README 维护"我们明确输的地方"表（单帧清晰度、多轮追问成本、可验证性）并给出补救——复评文化样板。
- **工程细节**：`bin/doctor.mjs` 环境自检（每条都跟"缺什么、怎么补"）；不打包 ffmpeg/yt-dlp 只调用用户装的那份；cookies 等同登录凭证的隐私提醒。

## 3. 不采用什么（为什么）

- **yt-dlp 在线下载链路**：我们只处理本地录制的环形缓存（45s），不做外站视频抓取（合规边界）。
- **实时视觉理解**：本项目明确是离线/事后工具——印证 AGENTS 复评表"实时游戏控制 100% 走 MCP 文本结构化状态"。
- 说话人分离等明确不做的能力（其实测 cam++ 短句误判结论可直接引用）。

## 4. 验证路径、预算边界与回退方案

- 验证路径：T-M4-03 切片门禁——模拟"矿洞晕倒+哈哈哈哈激增"→ 断言导出的切片草稿带 `.evidence.json` 时间码。
- 预算边界：每日视觉预算上限的计数口径（张数×计费 token）按其计费模型折算。
- 回退：若 ASR 本地链路太重，切片草稿可先走"字幕轨/已有字幕"两级（零 ASR 成本），ASR 后置。
