## T-M6-69 决策声明

> **T-M6-69 决策声明（2026-11-25）**：落地 `packages/game-bridge-mcp/src/` 的 `rule-schedule.ts`、`seed-table.ts`（新）、`planner.ts`、`state-hints.ts`（改造，另 `index.ts` 加两行导出）与 `tools/mock-harness/src/` 的 `bwf-farm-sim.ts`（新）、`bwf-replay-server.ts`（抽出通用 HTTP 层），守 ≤8 业务源码。与手册 §3.4/§3.6 的差异及理由：① **晨间多看一步**：手册晨间是「读信 → 浇水 → 收获」，但 BWF 作物概况只报当前地点，人在农舍根本看不到作物；实现在读信后加「收工前任何时刻、且人在农舍 → 先去农场」一步（LLM 中途交回驾驶权也能续上当天农活），其它地点不绕路。② **收工放在填充前**：手册把 22:00 收工列在填充之后，照做会 22:00 后继续钓鱼；实现把 bedtime 放在 fill 之前（到点不接新活），`bedtimeMinutes` 可配置（默认 22:00）。③ **购种多两道前置**：除营业时间/季末成熟/预算/空地外，`emptyTilled === null`（状态没农田段且无缓存）一律不动手；当前界面正是我们主动打开的商店时先 `buy` 再处理界面（`shopBuyDecision`），避免把买种界面当误开界面关掉。④ **日程步骤「决策即记、失败撤销」**：规则模式不再靠内部 phase 推进，否则同一段状态文本会反复 read_mail/water；FAILED/ERROR/TIMEOUT 回执撤销该步，允许当天换时机重试。⑤ **种子表**按手册初版（防风草 20g/4d、辣椒 40g/5d、小白菜 50g/4d，冬季不种），注释与文档均标注「以游戏内商店为准」；mock-harness 运行期源码受 depcruise 限制不能 import 业务包，仿真表复制一份并由 `rule-7day.spec.ts` 断言两份完全一致。⑥ **7 日测试的 N/A 口径**：`FarmDayRecord.opportunity` 记录「当天是否真的有机会做」（无未读/下雨/无可收/无可卖/周三或打烊/钱不够/无空地/季末熟不了），`loop || !opportunity` 才算通过，并额外断言 7 项各至少真正完成过一次，防止「全是 N/A」的空绿；`tools/soak-real/day-tracker.ts` 未改动，保持 T-M6-67 的 buySeeds/plant N/A 口径。⑦ **仿真复用回放服务 HTTP 层**：抽出 `startBwfHttpServer`（JSON/SSE、坏请求体、端口分配），S01–S06 保持全绿。⑧ **验证**：`pnpm test` 124 文件 / **1481 用例全绿**（含并行工单在 `apps/desktop-host` 新增的 13 例；本工单相关 `game-bridge-mcp` 14 文件 294 例）、分支 **90.47%**；`pnpm verify:gate` **7 过 / 0 跳过**。⑨ **真机未执行**：`ps` 确认当前无其它 soak 驱动，但 BWF 18080/18088 均未监听（curl 000），按「无第二个驱动 + 端点可达才跑」的约束跳过，VERIFY 登记「待真机」；新卡死按 T-M6-68 流程补剧本。
