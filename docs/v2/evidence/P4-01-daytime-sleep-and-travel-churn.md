# P4-01：秋8 白天浪费与折返的两处真实缺陷

真机 2026-11-28 秋8（构建 `960da9c`，采样至 09:50）暴露两处与「像人一样玩」直接冲突的行为。

## 缺陷一：06:50 用 sleep 收工，把整白天睡掉

真实决策序列（秋7 收尾 → 秋8 开始）：

```
07:10 take_items {"x":69,"y":13,"count":21,"items":"木材"}   - 凑木材做箱子
       water_crops {}                                        - 浇水
       take_items {"x":69,"y":18,"items":"喷壶"}              - 取喷壶
06:50 sleep {"force": true}                                   ← 才清晨就把整天睡掉
       read_mail {}
       take_items {"x":69,"y":18,"items":"斧头"}
```

`[DAY_DONE 1-秋7] endClock="第1年秋7日 06:50" money=1125->1125 (+0g) minStam=270/270 locs=3 watchdogs=0 fails=2`
——当天**零收益、零推进**，只走了 3 个地点。

根因：`state-hints.ts` 的体力低提示无条件写「…或 sleep({"force":true})」。体力 ≤50 且背包无 `[可食用]` 食物时，模型直接抓了 `sleep` 这个现成动作。

### 修复（`e075870`）

- 体力低提示按时间分流：白天（06:00–17:00）改为「先做零耗体事（forage 找大葱韭葱、找未认识村民 interact、read_mail、整理箱子），或去商店买吃的」；只有深夜才保留 `sleep({"force":true})` 收工
- 新增白天事实提示：`现在是白天 HH:MM：sleep 会跳过整天，白天别收工，做点能推进的事`

## 缺陷二：Farm ↔ Town 连续折返

```
travel_to Farm  →  travel_to Town  →  travel_to Farm  →  travel_to Town
```

验收脚本统计 `travelPingPong` 从 3 涨到 **5**（`travelTotal=10`，即 10 次跨地图移动里 5 次是「A→B→A」型折返）。每次理由都是「赶下一件事」，而前一处的事没做完就走了。

### 修复（`e075870`）

在环境事实提示里新增折返陈述：最近 `travel_to` 回执出现 `A → B → A` 时，列出该序列并说明「同一地点两次折返通常说明前一处的事没做完就走了」。只陈述事实，不指定该做什么。

## 验证

- `state-hints.spec.ts` **19/19 通过**，新增两组断言：
  - 白天低体力不含 `或 sleep({"force":true})`、含「白天」与「sleep 会把整天睡掉」；深夜同样状态则允许收工
  - `A → B → A` 回执触发折返提示；单次单向移动不误报
- `pnpm verify:gate` **8 过 / 0 跳过 / 0 待接线**
