# P4-01：重复失败动作上下文

## 决策声明

采用把「同一前置条件未变却反复失败」的重复事实汇总进规划提示，补上现有失败记忆只保留最后一条签名的缺口；参考 BWF 真实回执与 feiyu-os「假活」复核思想，自行实现。只陈述工具、次数与最近原文，不修改回执状态、不替模型决定玩法。

验证：以夏27 真机的 `upgrade_tool` 连续 3 次失败（钱差 1554g、缺 4 个铜锭）与熔炉「还在加工」重复探测为样本写回归；覆盖单次不报、不同原因不合并、逐字差异同因归并、窗口过期不计。再跑完整门禁。真实效果需下一保存点载入后观察。

## 真实反例（夏27，task-3575 汇总）

- `upgrade_tool` 在 12:10、15:30、16:50 各失败一次，原因相同：钱差 1554g、缺 4 个铜锭。
- `interact` 在 14:10 连续两次被拒：(69,15) 熔炉还在加工约 30 分钟。
- 失败记忆只保留最后一条签名与连续次数，模型看不到「同一缺口已重复几次」。

## 实现

- `buildRepeatedFailureSection(recentReceipts)`：最近 8 条中按「工具 + 原因前 24 字」归并，出现 ≥2 次才提示，列出次数与最近原文。
- 明确写出「同一失败原因连续出现说明前置条件没有变化」并点名可能的缺口类别（钱、材料、工具等级、加工剩余时间），但具体做什么仍由模型决定。
- 与空转提示、失败记忆并存，互不覆盖。
