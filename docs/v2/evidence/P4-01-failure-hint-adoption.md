# P4-01：具体方向提示的真机采纳证据（秋8）

## 观测

构建 `97402c9`（含 `concreteHintForFailure`），秋8 06:00 真实决策序列：

```
DEC take_items {"x":69,"y":16,"count":21,"items":"木材"}
REC FAILED   失败：(69,16) 四周没有可以站的地方
DEC take_items {"x":69,"y":15,"count":21,"items":"木材"}      ← 立刻换相邻格，未在同坐标重试
```

对照修复前的真实记录（秋7，构建 `960da9c` 之前）：

```
07:24:00 DEC take_items {"x":69,"y":16,...}
07:24:00 REC FAILED 失败：(69,16) 四周没有可以站的地方
07:24:09 DEC take_items {"x":69,"y":16,...}    ← 原样重试
07:24:09 REC FAILED 失败：(69,16) 四周没有可以站的地方
07:24:41 DEC take_items {"x":69,"y":16,...}    ← 第三次原样重试
07:24:41 REC FAILED 失败：(69,16) 四周没有可以站的地方
```

## 对照

| 指标 | 修复前（秋5/秋7） | 修复后（秋8） |
| --- | --- | --- |
| 同坐标连续重试次数 | 3 次 | **0 次**（首次失败后立即换 (69,15)） |
| 该会话内 `(69,16)` 总尝试 | 3 次 | 1 次 |

## 判据说明

账本里该条目状态：

```
take_items  (69,16)  count=4  first=秋5  last=秋7 13:50
```

count=4 ≥ 阈值 2，因此提示段会包含：

```
- take_items 在「(69,16)」已累计失败4次（首次见于秋5，跨日重复），最近一次（第1年秋7日 13:50）：失败：(69,16) 四周没有可以站的地方 → 取放箱前先 move_to 到箱子相邻的空地再调该工具
```

模型在下一轮直接把坐标从 16 换成 15，与提示给的方向一致。

## 诚实边界

- 这是**单次观测**（秋8 06:00 一次），不足以证明「从此不再重试」；但「首次失败后立即换相邻格」与「连续三次同坐标」是质的不同
- 尚未验证模型是否会**先** `move_to` 再取（当前是直接换坐标取，绕过了站位检查）——两者都避开了重复，但后者可能仍会失败
- 单次观测样本，未做多日统计；需要更长浸泡才能给出比例
