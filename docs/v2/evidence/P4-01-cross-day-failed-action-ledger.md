# P4-01：跨日失败动作账本（把学过的教训跨天带回来）

## 决策声明

秋5 真机暴露出一个比「重复失败」更本质的问题：**桌宠会忘**。夏28 已经把「(69,16) 四周没有可以站的地方 → 站位不可达，应先靠近或换站再取箱内物品」写进心得本，换到秋5 却又在**同一个坐标**连续失败 3 次。

采用**跨日失败动作账本**：把失败的「工具 + 关键参数」签名累计起来，跨日（乃至跨进程）保留，同一签名累计 ≥2 次就生成一段只陈述事实的提示。不采用的方案：

- 不把「不可达坐标」做成硬编码黑名单（那就是把玩法写死成规则树，违反 AI-first 红线）；
- 不让程序自动改写模型的参数（例如把 (69,16) 自动换成邻近格）——那是在替模型做选择；
- 不依赖心得本检索（检索口径是季节/地点/状态原文，天然召不回「某个坐标不可达」这类教训，且改检索口径会牵动整套排序）。

## 真实缺口（源码 + 真机核实）

| 环节 | 现状 | 后果 |
| --- | --- | --- |
| 失败记忆窗口 | `autodrive-host.ts` 只保留最近 8 条回执 | 换日后被新回执冲掉 |
| 重复失败提示 | `buildRepeatedFailureSection` 只扫最近 8 条 | 同上，跨日无效 |
| 心得本检索 | `StrategyNotebook.retrieve` 只用季节/地点/当日计划/状态原文打分 | 「(69,16) 不可达」这类坐标级教训召不回 |
| 失败沉淀 | 夜间复盘把教训写成自然语言 claim | 对「同一坐标」这种精确目标不可检索 |

## 实现

- 新增 `packages/game-bridge-mcp/src/failed-action-ledger.ts`
  - `extractFailureSubject`：从失败原文提取**稳定可复现**的关键参数——坐标 `(x,y)` 优先，其次引号内物品名，再次地点英文名，最后按首句前 20 字归并
  - `parseFailedActionRecord` / `recordFailedAction`：按「工具 | 关键参数」签名累计次数
  - `buildFailedActionLedgerSection`：只列出累计 ≥2 次的签名，写明次数、参数、最近时钟与最近原文；跨日时额外标注「首次见于 X 日」
  - `parseFailedActionLedgerFile` / `serializeFailedActionLedger`：落盘格式，损坏文件安全退回空账本
- 持久化：`StrategyNotebookFileSchema` 新增可选 `failedActionLedger` 字段，与心得本同文件按存档分文件保存，**跨日与跨进程保留**
- 接线：`failed-action-ledger-wiring.ts` 单独成文件，把 `llm-planner.ts` 保持在 **499 行**（T-M6-70 的 500 行硬门禁）
- 提示段注入位置：自主决策 prompt 的「长期经验」之后、「主人建议」之前

## AI-first 红线自检

提示段只写「哪个工具在什么参数上累计失败几次、最近原文是什么」，**不写**「必须/只能/立刻前往」等硬性措辞，**不判定**该怎么办，**不改**回执状态，**不替**模型选动作。回归里有一条断言专门盯这条线。

## 验证

- `failed-action-ledger.spec.ts` **9/9 通过**：只解析 FAILED、关键参数三类提取、跨日累计与跨日标记、不同签名互不干扰、账本上限截断、落盘往返与损坏文件兜底、接线只记 FAILED、措辞不含硬性词
- `llm-planner.spec.ts` **40/40 通过**（新增 2 条）：同一签名跨日累计后提示段确实进入自主决策 prompt 且含 `(69,16)` 与「累计失败2次」；成功回执不进账本、不产生提示段
- `pnpm verify:gate` **8 过 / 0 跳过 / 0 待接线**
  - 首次失败如实记录：新增文件的分支覆盖率不足导致全局 branches 89.87% < 90%，补测试后复跑通过（`.verify-gate/failure-2026-11-28T07-19-06-644Z.log`）

## 真机效果（已补验）

新构建重载后秋7 观测：`(69,16)` 取箱尝试 **0 次**（修复前 3 次连续同坐标），4 次 `take_items` 坐标全不同且全部成功。跨进程持久化也确认（秋5 签名在新进程秋7 仍保留，标注跨日）。详见 [P4-01-ledger-real-device-effect.md](./P4-01-ledger-real-device-effect.md)。
