# planner 两处「实现与直觉不一致」记录（2026-11-26，`[SIMULATION]`）

> 来源：为 Gate 3 分支覆盖率补边界用例时（提交 `e4f5db7`，`planner-utils.spec.ts` 13 例）发现两处实现语义与直觉/命名不一致。
> 处置：**本次不改实现**，只把现状钉进单测并在本文档留一行结论，是否改由 owner 定。两条均是纯函数行为，不涉及真机。

## 1. `NON_SELLABLE_RE` 排除「箱子」但不排除「木箱」——与 `hasChestItem` 的宝箱识别不对称

- **一行结论**：`listShippableItems` 依赖 `NON_SELLABLE_RE`（`planner.ts:102`），正则里是 `箱子` 两字连写，因此 **`木箱` 会被判为可出货**；而背包空间判定用的 `hasChestItem` 把 `木箱` 识别为箱子。同一个物品，一个函数认为是箱子、另一个认为是可卖货。
- **影响面**：满包自救时 `ship_items` 有可能把玩家当箱子存东西的 `木箱` 卖掉（BWF 侧若也拒收，则表现为一次失败动作，不是数据损坏）。
- **现状锁定**：`planner-utils.spec.ts` → `listShippableItems：值钱线索排最前，工具/种子/箱子被排除` 明确断言 `toContain('木箱')`，注释写明不对称。
- **若要改**：把正则的 `箱子` 换成 `箱`（注意会同时排除「箱子/木箱/宝箱/…」，需确认不误伤 `箱` 类可卖物），并同步该单测断言。

## 2. `pickTrashableFallback` 是「后命中覆盖前命中」，不是「取第一个可丢弃物」

- **一行结论**：`pickTrashableFallback`（`planner.ts:202`）遍历背包时对每个命中行执行 `candidate = name`，**最后一次命中生效**；因此背包里同时有 `鱼饵` 和 `防风草种子` 时返回的是靠后的种子，而不是先遇到的鱼饵。
- **影响面**：丢弃优先级实际由背包顺序决定，与「越靠前越先丢」的直觉相反；行为本身合法（都是低价值消耗品），但不可预期。
- **现状锁定**：`planner-utils.spec.ts` → `pickTrashableFallback：只挑不值钱消耗品，后匹配覆盖前匹配（如实记录遍历语义）` 用 `1: 鱼饵 x20 / 2: 锄头 / 3: 防风草种子 x3` 断言返回 `防风草种子`。
- **若要改**：循环里加 `if (candidate === null)` 即变成「先命中先生效」，需同步该单测；同时确认与 `pickAnyNonEssential` / `pickFurnitureToPlace` 的遍历口径是否要一起统一（后两者目前也是「后者覆盖」，但都是同类候选，优先级差异不如本条明显）。

## 3. 边界

- 以上结论只覆盖纯函数语义，`[SIMULATION]` 级；真实背包文本由 BWF `get_state` 提供，形态变化（如本地化改名）会让两个正则同时失效，届时需要真机取样再核。
- 本次未改动 `planner.ts` 任何一行，避免在单桌宠链路收敛期引入行为变化。
