# P4-01：低生命风险提前点名

## 决策声明

采用把生命偏低（≤50%）的事实提前写入生存提醒，替换原仅 ≤30% 才提示的阈值；参考 feiyu-os「假活」与 BWF 真实状态原则，自行实现。只把已存在的数值更早、更明确地点明，并给出「进矿洞/战斗前备好回血或先恢复」的前置提醒，**不指定具体玩法、不写死动作**。

验证：以夏28 真机（生命 47/120 = 39%，旧阈值不提示，随后 Farm↔Mine 往返 5 次白耗约 4 小时）为样本写回归；覆盖 39% 触发偏低、30% 仍走危险、满血两者都不触发、且不出现「必须/只能/立刻前往」等硬性措辞。再跑完整门禁。

## 真实反例（夏28，运行 0637ba4）

- 13:48 状态：生命 47/120（39%）、体力 170/270，地点 Farm。
- 当天 `travel_to` 序列：Farm → Mine → Farm → Mine → Farm，共 5 次，每次 40–50 分钟游戏时间。
- 每次返回 `COMPLETED` 且时钟推进，因此**既不算「无进展」也不触发卡死哨兵**。
- 旧 `buildSurvivalReminder` 仅在 `healthPct <= 30` 时警告，39% 完全不提示。

## 实现

- `healthPct <= 30`：保留原有「生命值危险」。
- `healthPct <= 50`（else if）：新增「生命过半偏低（47/120，39%）：进矿洞或战斗前先备好回血食物，或先恢复再冒险」。
- 措辞只陈述风险与前置条件，不包含动作选择。
