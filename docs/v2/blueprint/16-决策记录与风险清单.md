## 2. 需要后续产品决策

-   第一阶段桌宠渲染技术和素材格式；
-   主要声音模型和本地 GPU 基线；
-   是否提供云端同步服务；
-   主 Agent Runtime 是自研轻量 Runtime 还是先集成成熟框架；
-   直播第一目标平台；
-   第一阶段是否必须完成唱歌，还是先完成说话和口型；
-   是否把 Asset Studio 独立为桌面子应用；
-   多设备同步采用本地直连、用户自建服务还是托管服务；
-   商业发行模式和素材市场策略。

这些决策应通过 PoC 和成本评估完成，不应凭偏好直接锁定。

## 3. 主要风险

### 技术风险

角色跨形态一致性难；3D
生成模型输出不可直接动画化；中文语音自然度和延迟；唱歌模型质量、算力和许可；游戏更新导致
Mod 失效；Browser Use
对网站变化敏感；多设备事件冲突；长期记忆错误累积；Evolution Engine
自动修改引入回归。

### 平台风险

社交平台 API
权限变化；直播接口申请限制；平台对自动化行为限制；账号登录和风控；直播音乐版权；账号数据和观众隐私。

### 许可证风险

桌宠素材非商业限制；模型权重与 API 条款不同；GPL/AGPL
分发义务；生成模型输出权利不确定；字体、音乐、歌词和声音授权。

### 产品风险

一开始做太多模块；多角色过早引入；追求"像真人"导致过度主动；用户无法理解
AI 正在做什么；自动化行为难以撤销；角色人格在不同模型间漂移。

## 4. 风险缓解

单角色优先；模块化但不微服务过度化；先只读后写入；每个平台独立能力矩阵；角色资产版本化；事件回放；独立审查；低风险自动发布、高风险人工审批；许可证门禁；运行时权限和研发权限分离。

## 5. 最终产品判断

鲸屿最核心的长期资产不是某个模型、桌宠皮肤或 Harness，而是：

**Character Identity + Memory + Voice + Embodiment + Digital Life +
Asset Provenance + User Trust。**

只要这些核心身份和数据协议稳定，底层模型、工具、游戏和平台都可以持续替换与扩展。
