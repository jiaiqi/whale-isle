## 这套文档是什么

本目录把鲸屿从桌宠工作台扩展为开放式 AI Companion & Digital Life
Platform 的讨论，整理成可供产品、架构和 Coding Agent
长期使用的设计文档。

鲸屿的目标是让 AI
角色拥有稳定的数字身份、人格、记忆、关系、声音和外观；能够在桌面、游戏、浏览器、社区、直播和虚拟舞台中活动；并由独立研发
Agent 系统持续开发、测试、维护和升级鲸屿本身。

## 已确定的产品原则

1.  **单角色先行**：第一阶段只要求一个 AI 角色具备完整自主能力。
2.  **多桌宠先于多自主
    Agent**：其他角色先拥有独立形象、动画和基础声音配置，不立即拥有完整生活
    Agent。
3.  **身份与实现解耦**：Character Identity
    不等于模型、Harness、声音、外观或设备。
4.  **大模型优先生成**：图片、3D、声音通过 Provider
    调用现有模型；鲸屿负责编排、后处理、验证、版本和授权。
5.  **渐进式重构**：保留 Whale Isle
    已有可用工程资产，按领域边界迁移，不无条件推倒重写。
6.  **研发平面与运行平面隔离**：Evolution Engine
    在独立工作区修改、测试和发布，不让线上角色直接修改生产代码。
7.  **授权优先**：账号、浏览器会话、社交互动、直播、素材、音乐和声音均有明确权限与来源记录。
8.  **先验证再扩展**：每个里程碑有可复现验收测试，不以"Agent
    自称完成"作为完成标准。

## 文档使用规则

-   本文档定义目标和约束，不代表所有功能已经实现。
-   "现状"必须通过仓库代码、测试和运行证据确认。
-   平台开放
    API、开源项目维护状态和模型许可会变化，实施前必须重新核对官方文档。
-   新需求与本蓝图冲突时，Agent
    应先记录冲突并提出决策，不得自行改变核心原则。
-   每个实现工单必须链接需求、设计、验收标准和测试证据。
-   "候选项目"不等于已批准依赖；必须完成许可证、安全、维护状态和功能验证。

## 当前最重要的交付目标

**先让一个主 AI 角色完整跑通：**

桌面形象 → 人格与记忆 → 专属声音 → 自然对话与动作 → 星露谷游戏化身 →
游戏控制与协作 → 创作资产 → 直播和舞台。

其他角色先作为可展示桌宠，不提前引入多 Agent 全自主复杂度。
