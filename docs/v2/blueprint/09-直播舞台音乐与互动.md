# 09 --- 直播、舞台、音乐与互动

## 1. 目标

让主 AI 角色在直播或非直播状态下进行桌面/2D/3D
表演、说话、唱歌、跳舞、展示歌词、读取平台支持的直播事件、回应弹幕、识别关注/礼物等事件，并使用角色自己的声音和动作表现。

## 2. Live Runtime

拆分为： - Live Session Manager； - Platform Adapter； - Event
Ingestion； - Chat/Comment Queue； - Gift/Follow Event Processor； -
Speech Queue； - Performance Planner； - Stage Director； -
OBS/Streaming Output Adapter； - Audit & Replay。

平台适配器只负责接收平台支持的事件，不把平台业务逻辑写进角色核心。

## 3. 直播事件

统一事件类型： - `live.session.started` - `live.session.ended` -
`live.chat.received` - `live.follow.received` - `live.gift.received` -
`live.member.changed` - `live.song.requested` - `live.moderation.alert`

每个事件保留平台事件 ID、发生时间、来源、可用字段和去重键。

## 4. 弹幕处理

弹幕高峰不能每条都调用大模型。建议： 1. 入口去重和过滤； 2. 风险检测；
3. 事件分类； 4. 重要性排序； 5. 合并相似问题； 6.
选择少量值得回应的内容； 7. 生成回应草稿； 8. 经过策略检查； 9.
加入语音队列； 10. 记录回应结果。

支持观众点名、游戏相关问题、点歌、礼物感谢、普通聊天、垃圾内容过滤和直播主持模式。

## 5. 礼物和关注感谢

角色可根据事件类型和礼物信息生成感谢内容，但不能保证对每个事件都实时逐条语音回应。支持合并感谢、优先级和频率限制，避免语音队列爆炸。

观众身份记忆应最小化，并遵循平台和用户的数据策略。

## 6. 点歌

流程： 1. 收到点歌请求； 2. 检查曲库/授权； 3.
检查歌曲是否允许直播使用； 4. 获取歌词和伴奏（若授权）； 5.
生成演唱计划； 6. 选择角色 Singing Profile； 7. 生成/播放歌声； 8.
同步歌词； 9. 同步口型和舞台动作； 10. 记录演出结果。

不能默认任意歌曲都能直播。音乐、伴奏、歌词、录音和翻唱涉及不同权利。

## 7. 歌词系统

支持开启/关闭、双语歌词、当前行高亮、时间轴同步、字体和位置、OBS
输出以及桌面端/直播端不同显示策略。

歌词时间轴应与音频播放时钟同步，不依赖模型生成时间估算。

## 8. 舞台系统

同一角色可在桌面直接表演、2D 场景、3D VRM 舞台和 OBS 透明背景输出。

统一 Stage API： - load character； - load scene； - set expression； -
play animation； - start speech； - start singing； - show lyrics； -
transition scene； - stop performance。

## 9. 多角色舞台（后续）

第一阶段只要求一个主角。未来多角色表演需要舞台角色槽位、动作时间轴、音频混音、发言轮次、合唱分轨、舞蹈队形、角色间动作同步和资源调度。

## 10. 平台风险

抖音、Bilibili
等平台的直播开放接口、插件审核、消息连接和账号权限可能变化。必须通过官方开放平台申请和实测。不能将非官方逆向接口视为稳定生产依赖。

## 11. 验收

-   直播事件有去重；
-   弹幕峰值不会压垮模型调用；
-   语音队列可中断；
-   歌词与音频同步；
-   角色声音和动作一致；
-   直播结束后生成可查询的事件摘要；
-   平台断连时有降级提示；
-   歌曲和素材通过授权检查。
