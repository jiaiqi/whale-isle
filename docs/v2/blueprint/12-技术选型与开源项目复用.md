# 12 --- 技术选型与开源项目复用策略

## 1. 总原则

尽量复用成熟项目，但不把项目列表当作依赖清单。每个候选必须通过功能匹配、维护情况、许可证、安全、平台合规、部署复杂度、集成成本和可替代性审查。

## 2. Agent / Memory / Harness

  项目           候选用途                       处理建议
  -------------- ------------------------------ ---------------------------
  Letta          长期 Agent、记忆管理设计       重点研究设计，按需集成
  Mem0           记忆提取和检索                 Provider/Adapter 候选
  Graphiti       时间知识图谱、关系和事实变化   关系记忆候选
  OpenHands      软件研发 Agent 工作流          Evolution Engine 重点研究
  ACP            Coding Agent 连接协议          作为适配标准
  MCP            工具连接协议                   双向支持
  Agent Skills   Skill 格式                     兼容开放规范

## 3. Browser / Computer Use

  项目               用途
  ------------------ ----------------------
  Playwright         确定性浏览器自动化
  Browser Use        Agent 自主浏览
  Stagehand          语义化网页操作
  Browser MCP        连接本地浏览器的候选
  OS UI Automation   桌面应用操作基础

不要多个浏览器 Agent 同时争抢同一 Session。

## 5. 语音和音乐

  项目/方向          用途
  ------------------ ----------------------
  CosyVoice          中文/多语言 TTS 候选
  MOSS-TTS           声音设计和 TTS 候选
  在线实时语音 API   低延迟语音对话
  SVS 模型           歌声合成
  SVC 模型           授权音色转换
  FFmpeg             音频处理、混音、转码

普通 TTS 不应被当作歌声合成。

## 6. 游戏

-   Stardew Valley：SMAPI；
-   静态内容：Content Patcher；
-   动态角色同步：自研 Whale Isle SMAPI Mod；
-   未来按游戏分别开发 Adapter。

## 7. 社交平台

研究官方开放平台和经过许可的 API 优先。社区 MCP/CLI
项目只能作为参考或实验适配器。

候选参考： - Agent-Reach； - Bilibili MCP 社区项目； -
xiaohongshu-mcp； - Douyin Skills； -
Postiz（偏发布排期管理，不是完整社交生活系统）。

平台能力必须逐项验证，不能把非官方逆向能力当生产依赖。

## 8. 许可证策略

建立 `THIRD_PARTY_NOTICES.md` 和自动化许可证扫描。

重点区分源代码许可证、模型权重许可证、生成服务条款、角色图片和动画素材授权、音乐/歌词/声音授权、字体和图标授权、用户上传素材授权。

AGPL/GPL 项目如果要捆绑、修改或分发，需要合规评估。MIT
代码也不代表模型权重或素材可商用。

## 9. Build vs Reuse

优先复用：浏览器自动化、音视频处理、3D 建模和后处理、TTS/ASR
基础模型、MCP/ACP、Git/CI、游戏 Mod 框架。

鲸屿必须自己掌握：Character Identity、角色状态和表现编排、统一 Asset
Manifest、Agent/Embodiment
协议、权限与审计、多设备状态、游戏任务协作、Digital Life 编排、Evolution
Engine 的产品策略和验收。
