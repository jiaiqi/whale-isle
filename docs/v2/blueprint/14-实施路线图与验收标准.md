# 14 --- 实施路线图与验收标准

## 1. 总体顺序

先治理工程和研发流程，再完成单角色闭环，再扩展多角色和数字生活。

## 2. 阶段路线

### V2-00：仓库审计与架构冻结

交付：全仓审计、模块依赖图、Keep/Refactor/Rewrite/Retire、统一领域模型、统一路线图、许可证清单、测试基线。

验收：可重复构建；测试结果有报告；所有 NEXT
工单唯一；现状与目标差异明确。

### V2-01：Evolution Engine 最小闭环

交付：独立研发工作区、Worktree Manager、一个 Coding Agent
Adapter、测试执行、Review、PR 创建、失败报告。

验收：能从一个 Bug Report
创建分支；不修改生产目录；自动测试并生成证据；能提交
PR；失败时停止且不伪造成功。

### V2-02：单角色身份闭环

交付：Character Core、一个 Primary Agent
Runtime、Persona、Mood、Memory、Embodiment 和事件模型。

验收：更换模型不丢角色身份；同一角色在桌面和游戏引用同一 Character
ID；记忆有来源和置信度。

### V2-03：声音和表演

交付：Voice Profile、TTS
Provider、播放队列、情绪表达、表情和动作、口型基础同步。

验收：角色声音可配置；语音可中断；动作不冲突；有延迟和错误监控。

### V2-04：游戏化身与星露谷

交付：Stardew Adapter、Avatar Pack、SMAPI
Mod、游戏状态回传、动作回执、人机协作 Task Board。

验收：主角色游戏形象稳定显示；至少一组可重复游戏任务成功；用户与 AI
能分工；失败有恢复路径。

### V2-05：AI 创作工坊

交付：Media Generation Gateway、本地 Agent 生图入口、直接图片 API、3D
Provider、Asset Registry、Character Bible、Sprite QA、授权门禁。

验收：生成一套桌宠资产、一套星露谷游戏资产和一个可预览的 3D
角色候选；资产有来源、版本和许可状态。

### V2-06：Browser / MCP / Skills / Harness

交付：MCP Client/Server、Skills Registry、至少两个 Harness
Adapter、Browser Runtime、Computer Use Lease、独立 Profile。

验收：可连接一个外部 MCP；可向外提供一个鲸屿 MCP 工具；可加载一个
Skill；同设备不会发生 Agent 键鼠抢占。

### V2-07：直播与舞台

交付：Live Event Adapter、弹幕队列、礼物/关注事件、Stage
Runtime、歌词显示、Singing Provider。

验收：使用测试直播事件回放；语音、动作、歌词同步；断连有降级；音乐授权检查生效。

### V2-08：Digital Life / Social

交付：内容发现、内容理解、记忆、关系图、社交决策、平台
Adapter、用户授权工作流。

验收：先只读；能记录内容来源；能生成互动草稿；写入动作受权限控制；不绕过平台规则。

### V2-09：多桌宠

交付：多桌宠渲染、独立资产、基础动作、声音配置和桌面布局。

验收：多个桌宠同时显示；不要求多个完整 Agent
Runtime；主角色状态不被动宠影响。

### V2-10：多角色自主生活

交付：多 Runtime、多账号、多记忆空间、多设备协作、多角色直播/游戏和
Agent 间任务协商。

验收：数据隔离、账号隔离、资源仲裁、任务交接和故障隔离。

## 3. 每个工单必须包含

目标、用户价值、范围、非目标、依赖、接口、数据变更、权限影响、验收标准、测试、回滚和文档更新。

## 4. Definition of Done

只有满足以下条件才能标记完成： - 代码已实现； - 类型检查通过； -
单元测试通过； - 集成测试通过； - 相关回归通过； -
关键错误路径已测试； - 安全和权限已检查； - 文档已更新； -
日志和可观测性已接入； - 真实环境测试与 Mock 测试明确区分； - PR
有变更说明和测试证据。

## 5. 测试分层

Unit、Contract、Integration、E2E、Replay、Simulation、Real Device、Real
Game、Real Platform（只在许可和测试账号条件下）。

不能将 Mock 测试通过写成真实平台验证通过。

## V2.1 增补：自主游戏 Agent 验收门槛

V2-04 游戏阶段除完成游戏化身、状态回传和动作回执外，还必须验证自主目标规划、动态重规划、攻略检索与版本适用性判断、游戏经验积累、自然语言协商、明确指令执行、快捷停止和手动接管。

不得仅以“按固定脚本完成任务”作为游戏 Agent 验收。至少通过 `17-自主游戏智能与人机共玩系统.md` 中列出的背包管理、临时钓鱼/下矿、攻略冲突、用户建议、强制命令、紧急停止和手动接管场景。
