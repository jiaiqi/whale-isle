# 11 --- 安全、隐私、权限与治理

## 1. 安全原则

最小权限、默认拒绝、用户可撤销、账号隔离、密钥不入库、外部副作用需授权、关键操作可审计、运行和研发隔离、数据最小化、安全失败时降级而不是绕过。

## 2. 权限分级

  级别   行为                             默认策略
  ------ -------------------------------- --------------------
  P0     读取本地非敏感状态               可授权自动
  P1     读取公开内容/已授权内容          按账号权限
  P2     生成草稿、计划、预览             自动
  P3     可撤销本地变更                   按规则授权
  P4     对外评论、发布、关注、互动       默认确认或有限规则
  P5     私信、删除、账号安全设置、支付   每次明确确认

用户授权不能让平台禁止的行为变成允许。

## 3. 密钥管理

-   Windows Credential Manager / OS Keychain；
-   加密凭证库；
-   Provider 只拿短期、最小范围凭证；
-   日志自动脱敏；
-   导出配置默认不包含 Key；
-   支持轮换、撤销和过期；
-   Cookie 不进入普通配置 JSON；
-   不将凭证传给不可信插件。

## 4. Browser Profile 隔离

每个角色/账号独立
Profile。浏览器自动化和用户自己的日常浏览器分离，除非用户明确选择连接现有浏览器并授权。

## 5. Computer Use 互斥

同一设备只有一个自动化主控 Lease。用户键鼠输入可立即夺回控制权。Lease
有期限、心跳、撤销和超时释放。

## 6. 社交安全

不冒充真人、不伪造身份或经历、不绕过平台访问控制、不刷量、不随机评论、不发送骚扰内容、不在未授权情况下私信、不保存不必要个人信息。对外内容应符合平台规则和用户设置。

## 7. 记忆与隐私

用户可查看、纠正、固定和删除记忆；记录来源和置信度；敏感信息默认不提取或不长期保存；原始日志和主动回忆索引分开；数据保留期可配置；删除请求应覆盖相关衍生索引和备份策略。

## 8. 素材和声音授权

每个图片、模型、音频、音乐、歌词和声音模型必须记录来源、许可证和使用范围。

不得未经许可克隆现实人物声音；不得未经许可使用商业歌曲或伴奏直播；不得把非商业素材用于商业发布；不得因代码仓库是
MIT 就认定其中素材也可商用。

## 9. 插件安全

插件签名/来源、权限清单、沙箱或独立进程、网络和文件
Broker、资源限制、依赖扫描、许可证扫描、版本锁定、可撤销和崩溃隔离。

## 10. 数据分类

Public、User Content、Character Private、Account Secret、Live Audience
Data、Runtime Diagnostics、Development Artifacts。

研发 Agent 只接收解决问题所需的脱敏最小数据。

## 11. 安全事件处理

立即撤销相关权限、隔离插件或设备、保留必要审计、轮换泄露凭证、回滚不安全版本、通知用户并记录根因和修复措施。

## V2.1 增补：游戏控制权安全

自主游戏控制必须有明确控制模式和可抢占机制。Stop、Pause、Manual Takeover 和用户实时输入优先于任何 AI 计划；同一时刻不能让 AI 与用户争抢同一游戏角色。强制任务应有完成、取消、阻塞和超时后的释放规则。

对出售稀有物品、消耗关键资源等高影响且不可逆操作，可按用户设置要求二次确认。用户可以配置允许 AI 自主执行的动作范围。详细控制优先级见 `17-自主游戏智能与人机共玩系统.md`。
