# OWNER 操作清单（item 4 / `V2-P3-02`）：OBS 浏览器源前置 + 音频进 OBS

> 一页纸。三步都做完，鲸屿的 overlay 画面与声音就能进 OBS；每步都有**验证方式**和**还原方式**。
> 背景与证据见 [RUNBOOK-OBS-OVERLAY.md](./RUNBOOK-OBS-OVERLAY.md) 与 [P3-02 证据](./evidence/P3-02-obs-local-closure-verification.md)。

---

## 第 1 步：关闭 OBS「浏览器源硬件加速」（画面前置，必做）

- **操作**：OBS → 设置 → 高级 → 源 → 关闭「浏览器源硬件加速」（英文界面：Hardware acceleration）。
- **为什么**：本机实测开启时 `browser_source` 渲染全黑（连纯红静态页都黑），关闭后正常。不关它，OBS 里看不到任何 overlay 画面，而且无法判断是谁的问题。
- **验证**：终端跑 `pnpm obs:selfcheck`——输出 `BrowserHWAccel = false` 且结论为「前置满足」即通过。
- **还原**：想改回原设置，先确认红页自检为红色再改回 `true`，并记下「改动 → 验证 → 还原」三步。

## 第 2 步：开启 obs-websocket 并告诉鲸屿密码（自动验证与音频推流前置，必做）

- **操作**：OBS → 设置 → 控制台 → WebSocket 服务器 → 勾选「启用 WebSocket 服务器」，端口保持 **4455**，记下（或设置）密码。
- **交给谁**：把密码告诉开发会话（或直接贴进运行环境变量 `OBS_WEBSOCKET_PASSWORD`）。
- **验证**：终端跑 `pnpm obs:selfcheck --probe`——退出码 `0` 表示浏览器源能正常渲染（脚本只建临时场景、截图后自动删除，不动你的任何场景，不推流不录制）。
- **不用的代价**：没有密码，鲸屿无法自动验证 overlay，也无法走「零驱动零授权」的音频路径 A。

## 第 3 步：音频二选一（让鲸屿的声音进 OBS）

### 3A（推荐，零系统改动）：应用直接把音频推给 OBS

- **无需任何操作**：完成第 2 步即可。鲸屿把音频文件直接交给 OBS Media Source 播放，不装驱动、不弹授权窗、不改系统设置。

### 3D（备选，精确抓进程）：首次系统音频录制授权

- **何时用**：想精确只抓鲸屿（含 `afplay`）的实时输出时用 Core Audio process tap 方案。
- **操作**：首次启动该功能时，系统会弹一次「允许"鲸屿"录制系统音频」，点**允许**即可，仅此一次。
- **附加确认**：「系统设置 → 隐私与安全性 → 屏幕与系统音频录制」里确认鲸屿已勾选。

---

## 明确不需要做的事

- **不需要安装 BlackHole / Loopback 等虚拟声卡**（已核实非必需，且装系统级驱动未经你同意不做）。
- **不需要改动你的既有场景、推流或录制设置**；所有自动化只建临时对象并自动清理。
- 路径 B/C（OBS 自带的 macOS Audio Capture）本机不建议：B 会混进整机声音，C 实测抓不到 `afplay`。
