## 1. 可借鉴的方法与结构

### 1.1 先建立唯一角色锚点，再做变体

CrossPet 的 docs/prompts/角色生图提示词.md、角色目录定妆提示，以及 art/交接-API生图/新角色与新皮肤.md 都把角色定妆放在整套图之前：先以权威参考图确认角色，再选定获批的基础图；之后逐图或逐小批生成、确认，再扩展。后续提示要明确哪张图是角色身份锚点、哪张图只供姿态/服装/风格参考，不能让不同参考互相覆盖。

应用到小鲸时，角色身份来源固定为项目现有 blue-whale-maid WebM 抽帧与角色契约；本轮定妆样张作为场景图的新视觉锚点。场景图允许改变动作与环境，不得重设计五官、发型、头饰、女仆裙装或身体比例。

### 1.2 提示词分区，明确哪些能变

建议依次写明：

1. 任务与画布：素材用途、画布比例/尺寸、透明或指定底色。
2. 参考图角色：逐一列出身份参考、姿势参考、风格参考及各自权限。
3. 角色锁：头身比、发型与发色渐变、眼睛、头饰、服装结构、标志配件、固定配色、身体特征和左右侧约定。
4. 场景与姿态：一张图只讲清一个状态；动作、视线、手部、表情和道具之间有因果。
5. 绘制风格与构图：轮廓、线宽、阴影层数、细节密度、角色与留白比例、背景层级。
6. 不变量和禁项：列出禁止改变的身份元素、禁止漂浮/脱手道具、错误文字、边缘裁切、额外角色和效果。
7. 输出与质检：文件名、尺寸、alpha/底色、透明边缘、尺寸/体积和视觉核对点。

先写可观察的正向描述，再用简短禁项排除常见漂移，比只写“可爱/一致”更可复现。每个提示都应重复核心身份锁，不能只依赖上一轮对话记忆。

### 1.3 参考图锚定与一致性规则

- 声明身份锚点，并把一张获批样张作为后续场景统一参考；说明每张参考的具体用途，不要让身份图、服装图和风格图彼此覆盖。
- 用可视细节锁定角色：发色分区、眼睛形状与颜色、头饰和耳/尾所在侧、领结/围裙/鞋袜结构；不能只写角色名。
- “viewer left/right”按观察者方向写清；角色身上的单侧配件要固定在角色同一侧，姿态变换不等于水平镜像。
- 道具应由手握持、夹住、托住或与身体接触；动作意图须与表情、手势和道具呼应。
- 多状态图把可变部分限制为动作/表情/场景；连续动作的头部尺寸、身体比例、配色和基线保持稳定。
- 水彩、线稿或背景复杂度的风格参考单独说明；不得让风格参考覆写角色身份。

### 1.4 姿态库与特殊版式

art/姿态/ 与 art/规则/ 把姿态拆成可执行的局部约束。可借鉴“基准站姿、动作/情绪、场景特例”分层写法；不要把桌宠 Sprite 的全部规则机械套到中控台插画。

- 原地规则指出词义可能有歧义，应用脚是否离地、身体是否倾斜等画面事实消歧。
- 左右成对规则要求先做一侧，再以成稿编辑另一侧；不要用水平翻转破坏单侧饰品。
- 贴边/探头写明裁切边、头顶空间、露出比例和手抓边缘；仅在版式确实贴屏时使用。
- 多任务/彩蛋规则显式说明动作例外、参与者身份、彼此关系和道具接触，避免僵硬张臂、漂浮物件或角色串设定。
- mini 系列先定义独立比例、轮廓和可读性，再锚定批准的 mini sheet；跨批保持头身、五官、配色和单侧配件。CrossPet mini 约 2 头身并针对约 50px 显示简化细节；这是其桌宠规格，不是小鲸中控台场景图的硬性比例。

### 1.5 定妆后的检查清单

逐轮检查：身份特征是否齐全且左右正确；脸、发型、头饰和服装是否漂移；身体比例和线宽是否与定妆锚点一致；手和道具是否接触自然；轮廓是否完整；缩小后标志元素是否可读。失败时只改一个明确变量再生成，不以新图替换已经通过的身份锚点，除非重新走定妆确认。

## 3. 可以借鉴什么，不能直接拿什么

**可以借鉴**：角色锚定、先定妆再扩展、提示分区、参考图权限说明、固定身份/单侧细节、逐图校验、姿态拆分、失败时局部修订等创作方法。本文以本项目语言重新撰写，只保留方法与结构。

**不能直接拿**：CrossPet 的 characters/ 立绘、角色造型/文本设定、docs/prompts/ 提示词原文、角色或 mini 助手图片、皮肤和彩蛋素材。CrossPet 根 LICENSE 的 MIT 只覆盖源码；characters/LICENSE.md 将角色图、设计和提示词置于 CC BY-NC-SA 4.0，要求署名、非商业及相同方式共享。本轮没有把 CrossPet 图片作为 image_gen 输入，也没有把其角色作为小鲸原型。

小鲸身份参考来自本仓 packages/pet-renderer/assets/blue-whale-maid/ WebM 和 manifest；该角色素材在本项目登记为 DEV_ONLY_NON_COMMERCIAL，来源为 dsh-pet / ZipZipPipe，CC BY-NC-SA 4.0。因此新图继承小鲸角色素材的非商业范围，并按相同方式共享；OpenAI 生图服务条款不会消除角色来源约束。详见 [REFERENCE-crosspet.md](../../REFERENCE-crosspet.md)、[OPEN-SOURCE.md](../OPEN-SOURCE.md) 与 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)。

## 4. 小鲸身份锚点的项目依据

- packages/character-core/src/character-core.ts 中 DEFAULT_XIAOJING_BASE_PROMPT 与默认快照确认角色名、char_xiaojing、blue-whale-maid 和“傲娇干饭蓝鲸女仆”设定。
- packages/pet-renderer/assets/blue-whale-maid/manifest.json 确认资产包、来源和 DEV_ONLY_NON_COMMERCIAL 范围；实际身份视觉以待机、吃饭、女仆礼、傲娇回应等 WebM 抽帧为准。
- docs/v2/evidence/P2-character-studio-crosspet-verification.md 与 packages/shared-protocol/src/media.ts 定义 Character Bible 的参考图、发型、眼睛、配色、服装、比例、标志配件、表情规则、风格约束和禁改项字段，并记录候选图需审查后再晋升。
- 当前检索到的仓库文件中未发现独立持久化的 char_xiaojing CharacterBible JSON。故本次模板按 Character Bible 字段组织身份锁；视觉事实只从实际 WebM/manifest 与 CharacterCore 归纳，没有把其他 CrossPet 角色 Bible 当作小鲸设定。
