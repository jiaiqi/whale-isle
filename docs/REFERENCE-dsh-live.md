## 1. 结论摘要

多平台 RTMP 推流插件（摄像头/屏幕选区/画中画 + 视频号/抖音/快手/斗鱼/B站/YY/虎牙/CC/自定义多选同步）。**处于未完成态**，且是"模拟指标"的一个已证实样本。保留拉黑处置，仅吸收思想。

## 2. 已证实事实（README 自述）

- **模拟（演示）引擎**：Host 只维护推流状态与统计，"**码率/观看/时长为模拟值**，不产生真实网络推流"——虚假指标类逻辑（用户 SPEC 红线中"随机虚假指标逻辑"的对应物），严禁引入。
- **真实推流未闭环**：ffmpeg 真实推流当前推的是 `testsrc2` 彩条 + 440Hz 正弦音（640×360 H.264/AAC），**"浏览器预览画面尚未接入 ffmpeg 输入"**——不能作为成品参考。
- **SPEC 中"密钥回传"传闻未在 README 得到印证**：README 仅要求用户自行保存推流码（推流码明文配置属该类工具的正常形态）。但无许可证 + 源码未审计 + 已有模拟指标自述，维持最严处置；若未来需要定论，单开只读审计工单，**只读不改不复制**。

## 3. 采用什么（思想层面）

- **平台端点模板表**：各平台 RTMP 服务器地址模板 + 推流码获取方式指引（B站直播姬/抖音直播伴侣/快手/斗鱼/虎牙/YY/CC）——第二阶段 FFmpeg 多路推流模块（SPEC 冻结决策第 3 条的后半）的文档基础。
- **ffmpeg 自动检测/一键安装**：检测 → Homebrew 分支 → 静态编译包回退。
- **本地端到端验证法**：MediaMTX 起本机 RTMP（`rtmp://127.0.0.1:1935`）→ 推流 → `ffplay`/VLC 拉流验证——我们 RTMP 模块（若启动）的 `[SIMULATION]` 门禁剧本来源。
