## 0. 一页结论

- **母题「深海屿光」**：角色是深海中发光的数字生命体，控制台是守望它的灯塔。主色从系统蓝转向**鲸光青 `#3EE0CD`**，背景从纯黑转向**深海分层墨蓝**，品牌时刻用**极光渐变**。
- **信息架构从「插件平铺」重组为「六世界十页面」**：生命体（总览/角色/化身/生活）→ 能力面（智能体/创作工坊/游戏共玩/直播舞台）→ 系统面（进化引擎/安全治理）。现有 20+ 面板全部有新家（§5.3 映射表）。
- **四个签名组件回应蓝图四个硬要求**：声呐环（表现状态，05）· 回执芯片（真实回执，07）· 许可徽章（素材授权，06/11）· 控制权 HUD（用户控制权，17）。
- **六条设计铁律**：一个 AI 多种身体 / 决策透明可解释 / 控制权最高优先 / 回执不撒谎 / 授权显性化 / 本地优先·安静陪伴。
- **渐进演进不推倒重来**：v4「曜石」的玻璃材质、发丝线、统一 Shell、lucide、双主题、⌘K 全部承继（对齐蓝图 D-009 渐进式重构）。

## 2. 设计母题与六条铁律

### 2.1 母题：深海屿光

鲸屿的英文即 Whale + Isle。整套视觉围绕三个意象展开：

1. **海水分层（Strata）**：背景不是纯黑，而是由浅入深的墨蓝渐变加缓慢漂移的光斑——像透过海水看深度。信息层级 = 水深层级。
2. **生物发光（Bioluminescence）**：发光只给"活着"的东西——状态点、声呐环、主角色 Avatar、进行中的回执。死数据不发光，对比之下生命感自然浮现。
3. **灯塔守望（Lighthouse）**：控制台的存在感是"照亮但不打扰"：常驻快控与勿扰、随时可追问"为什么"、随时可停止与接管。

### 2.2 六条铁律（每条都对应蓝图条款）

| # | 铁律 | 蓝图依据 | 界面落点 |
| --- | --- | --- | --- |
| 1 | 一个 AI，多种身体 | MASTER §二 / 03 §1 | 角色身份卡常驻；化身页星座图；一致性检查徽章 |
| 2 | 决策透明可解释 | 17 §3/§13 | `.why` 解释框；每张目标卡带来源（自主/用户/共同）；知识卡带出处与置信度 |
| 3 | 控制权最高优先 | 17 §9 / 11 §5 | 控制权 HUD 四模式；紧急停止常驻；租约倒计时；优先级阶梯 |
| 4 | 回执不撒谎 | 07 §6 / 15 §3 | `.receipt` 三色芯片；FAILED 必带原因；UNCERTAIN 必带重试计数 |
| 5 | 授权显性化 | 06 §9 / 11 §2 | `.lic` 徽章全站贯穿；P0–P5 阶梯；商用清洗提示 |
| 6 | 本地优先·安静陪伴 | 01 §6 / 05 §5 | 凭证入钥匙串提示；饭碗预算常驻侧栏；勿扰一键；「沉默是选择」 |

## 3. 设计语言 v5「潮汐」

### 3.1 色彩

**暗色主题「深海」（默认）**，亮色主题「晨汐」对等实现（同一套语义变量，非简单反色）。

| Token | 暗色 | 语义 |
| --- | --- | --- |
| `--bg` | `#04070D` | 深海底；配 `.strata` 三层径向光斑 + 缓慢漂移动画 |
| `--surface` | 玻璃 `rgba(15,28,45,.62)` + blur30 | 卡片材质 |
| `--tide` | `#3EE0CD` 鲸光青 | 角色生命力、主交互、选中态、声呐 |
| `--blue` | `#4EA8FF` 海流蓝 | 进行中、信息、用户侧 |
| `--green` | `#35D49A` 回执绿 | COMPLETED、健康、授权通过 |
| `--amber` | `#FFC247` 米黄 | 预算/饭碗、UNCERTAIN、待人工、NC 素材 |
| `--violet` | `#B48CFF` 灵光紫 | AI 创造、研发平面、记忆 Self |
| `--red` | `#FF6B6B` 警示红 | FAILED、危险、直播红点、权限拦截 |
| `--aurora` | 青→蓝→紫 115° | 仅品牌时刻：Hero、Avatar、关键 CTA、进度峰值 |

**用色纪律**：一屏主色 ≤1 处高亮块；发光元素每屏 ≤6 个；极光渐变不做大面积铺色；正文永远 `--text-1/2/3` 三阶灰蓝。

### 3.2 材质七层（承 v4 曜石，色温深海化）

L1 深海分层底 → L2 玻璃卡（blur30+saturate）→ L3 发丝线（半透明蓝白描边）→ L4 内高光 → L5 柔影两级 → L6 文本光泽（`grad-text`）→ L7 状态光晕（只给活性元素）。实现全部收敛在 `tokens.css`，页面零重复定义。

### 3.3 字体与排版

- 界面字体：系统栈（SF Pro / PingFang SC）；数据与 ID 一律 `--font-mono` + tabular-nums。
- 分区标题 `.sec-h`：10–11px · 大写 · 字距 1.8px · 右侧细线延伸——整页的"呼吸节拍"。
- 正文 12–13.5px 行高 1.65–1.8；说明性文字用 `.note`（11.5px 三阶灰）。
- 数字仪表（饭碗、指标盘）用大号 tabular 数字，小数不抖动。

### 3.4 圆角 / 动效 / 图标

- 圆角阶：6 / 9 / 12 / 16 / 20px；胶囊一律 980px。
- 三条缓动：标准 `--ease`、出场 `--ease-out`、弹性 `--ease-spring`（开关滑块专用）。
- 签名动效：声呐脉冲 `sonar-ping`（3.2s 三环错相）、气泡上浮 `bubble-up`（事件流入场）、潮汐呼吸 `tide-glow`（声呐核心）、光斑漂移 `drift`（30s 交替）。全部遵守 `prefers-reduced-motion`。
- 图标：lucide 全站统一，语义固定——见 §4.7 图标语义表。

## 4. 签名组件规范

### 4.1 声呐环 Sonar（表现状态的唯一表达）

- 结构：核心圆（图标+辉光）+ 三层错相扩散环 + 下方 mono 状态标签。
- 九种表现状态（05 §2）：idle/listening/thinking/speaking/singing/dancing/gaming/reacting/resting；颜色映射：青=活跃、紫=表演（唱/跳）、琥珀=休息/静默、红=告警、灰=离线。
- 出现位置：总览 Hero、直播导演台、（未来）桌宠菜单。同一时刻全站只表达一个状态，以 Embodiment Runtime 仲裁结果为准。
- 禁止：用声呐环表达任务进度或加载——那是 `.meter` 与 `.steps` 的职责。

### 4.2 回执芯片 Receipt（真实执行回执）

| 芯片 | 语义 | 必带信息 |
| --- | --- | --- |
| `COMPLETED`（绿） | 已验证的真实完成 | 耗时 / 回执 ID |
| `IN_PROGRESS`（蓝） | 执行中 | 预计剩余 |
| `UNCERTAIN`（琥珀） | 模型不确定，等待旁观验证或重试 | 重试 n/m |
| `FAILED`（红） | 真实失败 | 失败原因（一句话） |

- 蓝图依据：07 §6「不能让模型只发出动作就认为成功」；仓库铁律「严禁把大模型台词当成任务完成」。
- 硬规则：FAILED 与 UNCERTAIN **永远不允许**被样式弱化成绿色；语音播放回执 `PLAYED` 复用绿色语义。

### 4.3 许可徽章 License（授权门禁的视觉语言）

`MIT`（绿）/ `APACHE-2.0`（蓝）/ `CC BY-NC-SA 4.0`（琥珀）/ `UNLICENSED`（红）/ `DEV_ONLY_NON_COMMERCIAL`（琥珀，自动附「商用前须清洗」提示）。
出现位置：每个资产卡、每个账号卡、每条攻略知识、每个声音模型。NC 素材进入任何"商用/直播"上下文时徽章升级为红色并阻断确认按钮（对齐 11 §8 与记忆中 D5 豁免边界）。

### 4.4 控制权 HUD（用户控制权）

- 四模式分段：自主 / 协作 / 指令 / 手动接管（17 §9.1），当前模式高亮并附一句话模式说明。
- 常驻紧急停止（`Space`）+ 接管（`T`）；租约到期时间、心跳、释放条件并入右栏 ControlLease 卡。
- 优先级阶梯文案固定：紧急停止/接管 > 强制命令 > 直接任务 > 共同计划 > AI 自主目标 > 待机（17 §9.2）。
- 尺寸分级：完整版（游戏页）→ 迷你版（总览快控）→ 桌宠菜单版（未来）。语义一致，仅密度不同。

### 4.5 气泡 Bubble（事件流与对话的统一形态）

AI 气泡鲸光描边（可带「内心戏」角标，对应 D11 可开关外放）、用户气泡海流蓝、系统事件虚线灰。事件流过滤按世界分组（游戏/直播/记忆/资产/进化）。

### 4.6 记忆卡 Memory（五类记忆）

类型色标：Working 蓝 / Episodic 紫 / Semantic 青 / Relational 绿 / Self 琥珀。卡上必有：置信度条、来源事件、保留策略、用户固定标记。操作三件套：查看 / 纠正 / 删除（08 §8、11 §7）。

### 4.7 图标语义表（防漂移）

侧栏分三组（即 MASTER 的六个产品世界 + 治理平面）：

```
生命体 · Lifeform      能力面 · Capability        系统面 · System
  总览 Overview          智能体 Agent               进化引擎 Evolution
  角色 Character         创作工坊 Creative Studio    安全治理 Security
  化身 Embodiment        游戏共玩 Game
```

导航规则：侧栏即世界地图（每项带副标题）；当前项鲸光左灯条；⌘K 可跳页面并执行全局动作；顶栏右侧常驻全局状态（语音、勿扰、直播红点、主模型延迟）与主题切换。

1. 世界断言区（Hero/身份/HUD 之一）——回答"我现在在哪、谁在做主"

3. 证据区（回执流 / 事件流 / 审计）——回答"发生了什么、凭什么信"
4. 右栏上下文（可选）——租约、预算、验收清单、原则卡片

## 6. 关键体验流程（UX 剧本）

### 6.1 决策透明流「为什么这样做」

触发：用户点击任意 `.why` 解释框或 `/why`。
展示：目标（来自哪个时间尺度）→ 候选方案对比（收益/代价/风险/兴趣四维评分）→ 已选动作 → 真实回执 → 反思更新（经验入库）。对应 17 §3 七问；不展示完整思维链，只展示可追问的结论链。

### 6.2 控制权切换流

用户按 `Space` → 全站红色横幅态（HUD 进入"用户持有"）→ AI 当前动作回执标记 `CANCELED_BY_USER` → 租约状态卡显示"用户持有，R 交还"。按 `T` 接管 → HUD 切「手动接管」→ AI 只保留观察与建议气泡（若允许）。恢复路径永远单向可见，无隐藏状态。

### 6.3 生成-审核-发布流（创作工坊）

Brief → 生成（Provider 可切换）→ 候选区（≥2 候选，评分可见，**不自动覆盖已发布资产**）→ 后处理 → 自动 QA（尺寸/帧数/透明边界/调色板）→ 人工预览（review_required）→ 授权门禁（lic 徽章校验，NC 进商用上下文即拦截）→ 发布版本（hash + provenance 落库）→ 运行时热切换 + 一键回滚。对应 06 §8 十态。

### 6.4 点歌授权流（直播）

请求入队 → 曲库命中 → 四项授权检查（歌曲/伴奏/歌词/直播使用范围）逐项亮灯 → 任一未授权即红色拦截并给出替代曲目 → SVC 合成 → 歌词时间轴同步预览 → 演出回执入摘要。对应 09 §6。

### 6.5 记忆纠正/删除流

记忆卡「纠正」→ 原文与修改并排 → 保存生成修订记录（保留来源）→ 衍生索引更新提示；「删除」→ 确认框列明覆盖范围（原始事件/摘要/索引/备份策略）→ 审计日志留痕（10 §11：不得删除审计记录）。对应 11 §7。

### 6.6 问题反馈 → 进化流

直播/游戏中点「这里有问题」→ 自动附脱敏上下文（版本/时间窗/回执/事件 ID；截图需明确授权）→ 进化引擎 Triage → 看板流转 → PR → 按自主等级审批 → 维护窗口发布 → 回滚待命。用户侧全程可看工单状态（10 §5）。

## 7. 状态与回执语言（全站统一）

| 维度 | 规则 |
| --- | --- |
| 回执 | `.receipt` 四态见 §4.2；游戏动作、语音播放、资产生成、发布部署共用同一语言 |
| 仿真与真机 | 沙盒数据一律带 `[SIMULATION]` 琥珀徽章；真机验收项在页面显示「待真机」灰态（AGENTS §2.4 铁律，禁止冒充） |
| 不确定 | 置信度 <0.6 的记忆/知识在 UI 上呈"灰度"（降透明+灰点），文案模板「我不确定，依据是…」 |
| 额度 | 不可查询的余额显示「未知 / 不可查询」，禁止编造数字（04 §10） |
| 空态 | 每个列表空态给出"下一步动作"按钮，不做纯插画空态 |

## 8. 无障碍 · 性能 · 工程约束

- **动效降级**：全部动画包 `prefers-reduced-motion` 逃逸（承 v4）。
- **对比度**：正文对深海底 ≥7:1；三阶文字只用于弱化层级，不承载关键操作。
- **键盘**：⌘K 全局；紧急停止 Space；接管 T；所有 `.seg` 支持 Tab + 方向键（实现期补 aria）。
- **零网络依赖**：设计稿与组件库全部本地（lucide 本地 vendored）；运行期 UI 同样要求离线可用（对齐 D14 独立运行硬约束）。
- **性能预算**：首屏交互 <100ms 的纯 CSS 方案优先；声呐/漂移动画仅用 transform/opacity（GPU 合成层）。
- **主题对等**：任何新组件必须在两主题下手工走查；禁止只在暗色下调好的发光。
